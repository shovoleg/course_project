# course_project на Synology DS923+

Новый NAS: короткий путь в `razvernut.md`. Этот файл описывает, как поставить текущую версию поверх уже работающего стека и не сломать базу, а также HTTPS, Google, GitHub и ImgBB.

Сайт открывается так:

`http://LAN-IP-NAS:8010`

После миграции на главной будут статистика, последние позиции и облако тегов. Проверка контейнера отдельно:

`http://LAN-IP-NAS:8010/health`

Ответ должен быть `ok`.

## Что не менять

`docker-compose.yaml` не заменяйте. Образы те же: `webdevops/php-nginx-dev:8.4` и `mysql:8.4.4`. База `db_project`, том `db-data`. Порт сайта `8010`.

Не удаляйте проект в Container Manager и не удаляйте том `db-data`. Иначе сотрётся база.

Не пробрасывайте на роутере `3306`, `8010`, `5000` и `5001`.

## 1. Заменить только код

1. Скачайте новый архив `course_project.zip`.
2. Распакуйте его на компьютере. Внутри должны быть `docker-compose.yaml`, `zapusk-na-synology.md` и папка `app`.
3. На NAS откройте File Station, папка `/volume1/docker/course_project`.
4. Старую папку `app` переименуйте в `app-old`. Не удаляйте её, пока новый сайт не откроется.
5. Загрузите новую папку `app` в ту же `course_project`. Рядом с ней должен остаться прежний `docker-compose.yaml`.
6. Включите показ скрытых файлов. В новой папке обязан быть `app/.env`.

Контейнеры перезапускать не нужно: код примонтирован как `./app:/app`.

## 2. Поставить пакеты заново

В архиве нет `vendor`. Его собирает Composer внутри контейнера.

1. Container Manager → Контейнер → `course_project-app-1` → Действие → Открыть терминал.
2. Выполните:

```sh
composer install --no-interaction
php bin/console doctrine:migrations:migrate --no-interaction
chown -R application:application /app/var /app/vendor
```

Первая команда скачивает PHP-пакеты. Вторая создаёт таблицы в MySQL и добавляет администратора. Третья отдаёт кэш пользователю PHP. Без неё сайт часто падает с ошибкой прав на `var/cache`.

Интернет на NAS для `composer install` нужен. Дождитесь окончания, не прерывайте.

Если миграция пишет, что уже применена, это нормально. Если пишет, что таблицы уже есть, не запускайте её повторно на другой базе и не удаляйте том.

## 3. Войти

Откройте `http://LAN-IP-NAS:8010`.

Администратор:

- почта `admin@example.com`
- пароль `admin12345`

Сразу смените пароль через регистрацию отдельного пользователя не получится: пароль администратора меняется только в базе. Для защиты курса этого хватает, пока сайт в домашней сети. Перед выходом в интернет пароль надо сменить.

Регистрация с главной создаёт кандидата. Роли рекрутера и администратора выдаёт администратор: Пользователи → выбрать строку → Роли. Кнопок в строках таблицы нет, сначала отмечается строка, потом кнопка на панели сверху.

Чёрная полоса внизу страницы — панель Symfony в режиме разработки. Это не ошибка.

## 4. Что уже можно проверить без ключей

Без Google, GitHub и ImgBB работают:

- регистрация и вход по почте;
- русский и английский, светлая и тёмная тема;
- библиотека атрибутов;
- позиции, правила доступа, дублирование;
- профиль с автосохранением раз в 7 секунд;
- CV, публикация, отметки «нравится»;
- обсуждение позиции, новые сообщения появляются сами через несколько секунд;
- поиск в шапке.

Вход через Google и GitHub на странице входа виден, но без ключей вернёт предупреждение. Загрузка фото тоже скажет, что хранилище не настроено. Остальной сайт от этого не ломается.

## 5. HTTPS и обратный прокси

Сайт снаружи открывается только по HTTPS. Порты `8010`, `3306`, `5000` и `5001` на роутере не пробрасывать.

Let's Encrypt не выдаёт сертификат на голый IP. Нужно имя. На DSM: **Панель управления → Внешний доступ → DDNS → Добавить**. Поставщик Synology, например `courseproject.odotibmebel.synology.me`. Это имя должно указывать на белый IP роутера. На роутере пробросьте только `443` на IP NAS, порт `443`.

Сертификат: **Панель управления → Безопасность → Сертификат → Добавить → Получить сертификат от Let's Encrypt**. Домен — то же имя DDNS. Почта любая ваша. Если запрос не проходит, сначала проверьте, что `443` уже проброшен и имя открывается снаружи.

Обратный прокси: **Панель управления → Портал для входа → Дополнительно → Обратный прокси-сервер → Создать**.

Источник:

- протокол `HTTPS`
- имя `courseproject.odotibmebel.synology.me`
- порт `443`
- включить HSTS не нужно, пока вход не проверен

Назначение:

- протокол `HTTP`
- имя `localhost`
- порт `8010`

Затем **Безопасность → Сертификат → Настройки → Настроить** и для этого правила прокси выберите сертификат Let's Encrypt.

Проверка: `https://courseproject.odotibmebel.synology.me` открывает сайт, а `https://courseproject.odotibmebel.synology.me/health` отвечает `ok`. Локально по-прежнему можно `http://LAN-IP-NAS:8010`.

В `app/.env` после этого замените строку:

```
DEFAULT_URI=https://courseproject.odotibmebel.synology.me
```

Подставьте своё имя. Контейнер `course_project-app-1` перезапустите.

## 6. Google и GitHub

Ключи пишутся в `app/.env` на NAS, не в compose. Пустые значения уже есть. Вход через соцсеть заработает только после HTTPS: Google не принимает callback на `http://192.168.x.x:8010`.

Google: [Google Cloud Console](https://console.cloud.google.com/) → создать проект → **APIs & Services → OAuth consent screen** → External → указать почту → scope `email` и `profile`. Затем **Credentials → Create credentials → OAuth client ID → Web application**. Authorized redirect URI, точно:

```
https://courseproject.odotibmebel.synology.me/connect/google/check
```

Пока приложение в режиме Testing, добавьте свою почту в Test users. Скопируйте Client ID и Client secret.

GitHub: [GitHub Developer Settings](https://github.com/settings/developers) → **OAuth Apps → New OAuth App**. Homepage URL — `https://courseproject.odotibmebel.synology.me`. Authorization callback URL:

```
https://courseproject.odotibmebel.synology.me/connect/github/check
```

Сгенерируйте Client secret.

В File Station откройте `app/.env` и впишите четыре значения без кавычек и пробелов:

```
GOOGLE_CLIENT_ID=сюда-id
GOOGLE_CLIENT_SECRET=сюда-secret
GITHUB_CLIENT_ID=сюда-id
GITHUB_CLIENT_SECRET=сюда-secret
```

Перезапустите контейнер `app`. На DSM время должно быть синхронизировано по NTP. Входить надо по `https://имя`, не по порту `8010`: иначе callback не совпадёт с тем, что записан в Google и GitHub.

## 7. Фото через ImgBB

Фото не сохраняются на NAS и не пишутся в MySQL. Бесплатно: [api.imgbb.com](https://api.imgbb.com/) → Get API Key (без карты).

В тот же `app/.env`:

```
IMGBB_API_KEY=сюда-key  # берётся с https://api.imgbb.com/ (бесплатно, без карты)
```

Перезапустите контейнер `app`. В профиле поле Personal Photo принимает файл перетаскиванием. В базе остаётся только ссылка `https://i.ibb.co/...`.

## 8. Если не открылось

Страница 500 сразу после замены `app`.

- Миграция ещё не выполнена. Вернитесь к шагу 2.
- В журнале контейнера `app` ошибка `Permission denied` на `var/cache`. Повторите `chown`.

`composer` не найден.

- Терминал открыт не в контейнере `course_project-app-1`, а в контейнере базы. Нужен именно `app`.

Миграция не видит базу.

- Контейнер `database` запущен, в журнале есть `ready for connections`.
- `DATABASE_URL` в compose по-прежнему указывает на хост `database` и базу `db_project`.

Архив на Windows или в File Station открывается как повреждённый.

- Нужен архив из этого шага, не старый `course_project.zip` от страницы-заглушки.

После перезагрузки NAS контейнеры не поднялись.

- Container Manager в Центре пакетов запускается вместе с системой.
- Контейнеры не были остановлены вручную. `unless-stopped` не поднимает то, что выключили сами.
